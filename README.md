# คำชี้เเจง

1. ## ข้อมูลนำเข้า
{72, 91, 65, 88, 79}

2. ## ผลลัพธ์ที่ต้องการ 
อาร์เรย์คะแนนสอบที่ถูกเรียงลำดับจาก มากไปน้อย {91, 88, 79, 72, 65}

3. ## ($n$): 
จำนวนสมาชิกทั้งหมดในอาร์เรย์คะแนนสอบ

4. ## แนวคิด:
เปรียบเทียบข้อมูลที่อยู่ติดกันคู่ต่อคู่ หากตัวหน้าค่าน้อยกว่าตัวหลัง ให้ทำการสลับตำแหน่ง (Swap) เพื่อให้ค่ามากทยอยย้ายไปอยู่ด้านหน้า ในแต่ละรอบของการวนลูปหากไม่มีการสลับข้อมูลเกิดขึ้นเลย (swapped == false) แสดงว่าข้อมูลเรียงลำดับเรียบร้อยแล้ว จึงหยุดการทำงานได้ทันที

5. ## คำสั่งหลักที่ใช้วิเคราะห์คือ 
คำสั่งเปรียบเทียบข้อมูล (scores[j] < scores[j + 1])

6. ## การวิเคราะห์จำนวนครั้งที่คำสั่งหลักทำงาน:
กรณีข้อมูลเรียงจากมากไปน้อยอยู่แล้ว (Best Case): ลูปนอกทำงานเพียง 1 รอบ และลูปในทำการเปรียบเทียบเท่ากับ $n - 1$ ครั้ง แล้วหยุดทำงานทันที (สลับข้อมูล 0 ครั้ง)  
กรณีข้อมูลเรียงย้อนกลับจากน้อยไปมาก (Worst Case): ลูปทำงานครบทุกรอบ ได้จำนวนครั้งการเปรียบเทียบรวมเท่ากับ $\frac{n(n-1)}{2}$ ครั้ง (สลับข้อมูล $\frac{n(n-1)}{2}$ ครั้ง)  

7. 
## Best Case: 
ข้อมูลเรียงลำดับเรียบร้อยแล้ว ใช้เวลาทำงานน้อยที่สุด

## Worst Case: 
ข้อมูลเรียงย้อนกลับทั้งหมด ต้องสลับข้อมูลทุกครั้งที่เปรียบเทียบ

## Average Case: 
ข้อมูลสุ่มกระจายทั่วไป

8. ## Time Complexity (Big O, Omega, Theta):  
Big O (Worst Case): $O(n^2)$
Big Omega (Best Case): $\Omega(n)$ (เฉพาะแบบปรับปรุงที่มี flag swapped)
Big Theta: ไม่สามารถระบุภาพรวมเป็น Theta เดียวได้เนื่องจาก Best Case และ Worst Case มี Complexity ต่างกัน (แต่ถ้าเป็น Bubble Sort แบบปกติจะตอบ $\Theta(n^2)$)

9. ## Auxiliary Space Complexity:
$O(1)$ เนื่องจากทำการจัดเรียงภายในอาร์เรย์เดิม (In-place) ใช้พื้นที่หน่วยความจำเพิ่มเติมเพียงแค่ตัวแปรชั่วคราว



10. ## ข้อเสนอแนวทางปรับปรุงอัลกอริทึมให้มีประสิทธิภาพมากขึ้น
หากต้องการประมวลผลข้อมูลขนาดใหญ่ เช่น $n = 100,000$ ควรเปลี่ยนไปใช้อัลกอริทึมที่มี Time Complexity ระดับ $O(n \log n)$ 
ดังนี้:Quick Sort หรือ Merge Sort: มี Time Complexity ในกรณีเฉลี่ย (Average Case) เป็น $O(n \log n)$  

สำหรับข้อมูล $100,000$ ค่า จะใช้เวลาในการประมวลผลเทียบเท่าการทำงานเพียงประมาณ $100,000 \times \log_2(100,000) \approx 1,700,000$ ครั้ง ซึ่งประมวลผลเร็วกว่า Bubble Sort หลายพันเท่า

Heap Sort: ให้ Time Complexity เป็น $O(n \log n)$ ในทุกกรณี (ทั้ง Best, Worst, Average Case) และใช้ Auxiliary Space เพียง $O(1)$ เหมือนกับ Bubble Sort

{91, 88, 79, 72, 65}Bubble Sort แบบปกติ (Unoptimized):จำนวนการเปรียบเทียบ:  $\frac{5(5-1)}{2} = \mathbf{10}$ ครั้ง (วนลูปทำจนครบทุกรอบแม้ข้อมูลจะเรียงแล้ว)จำนวนการสลับ: $\mathbf{0}$ ครั้งBubble Sort แบบปรับปรุง (Optimized):จำนวนการเปรียบเทียบ: $N - 1 = \mathbf{4}$ ครั้ง (ตรวจสอบเฉพาะรอบแรก แล้วหยุดทันทีเพราะ swapped เป็น false)จำนวนการสลับ: $\mathbf{0}$ ครั้ง

## ตอบคำถามวิเคราะห์
# Bubble Sort แบบปกติกับแบบปรับปรุงมี Best Case ต่างกันอย่างไร?  
แบบปกติ: มี Best Case เป็น $O(n^2)$ เพราะถึงแม้ข้อมูลจะเรียงมาเรียบร้อยแล้ว โปรแกรมจะยังคงเปรียบเทียบข้อมูลไปเรื่อยๆ จนครบ $\frac{n(n-1)}{2}$ ครั้ง
แบบปรับปรุง: มี Best Case เป็น $O(n)$ เพราะมีตัวแปร swapped ตรวจสอบ หากวนลูปรอบแรกแล้วไม่มีการสลับเกิดขึ้นเลย จะหลุดออกจากลูปทันที ทำการเปรียบเทียบเพียง $n - 1$ ครั้ง  

# Worst Case ของทั้งสองวิธีต่างกันหรือไม่?  
ไม่ต่างกัน: ทั้งสองแบบมี Worst Case เท่ากันคือ $O(n^2)$ และมีจำนวนครั้งการเปรียบเทียบข้อมูลเท่ากันคือ $\frac{n(n-1)}{2}$ ครั้ง ในกรณีที่ข้อมูลเรียงย้อนกลับทั้งหมด

# หากมีข้อมูลจำนวน 100,000 ค่า ควรเลือกวิธีนี้หรือไม่?
ไม่ควรเลือก: เนื่องจาก Bubble Sort มีประสิทธิภาพระดับ $O(n^2)$  หาก $n = 100,000$ จำนวนครั้งการเปรียบเทียบในกรณี Worst Case จะสูงถึงประมาณ $\frac{(100,000)^2}{2} = 5,000,000,000$ ครั้ง (5 พันล้านครั้ง) ซึ่งส่งผลให้โปรแกรมทำงานช้ามากอย่างมีนัยสำคัญ
