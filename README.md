1. ## ข้อมูลนำเข้า

3. ## ผลลัพธ์ที่ต้องการ 
อาร์เรย์คะแนนสอบที่ถูกเรียงลำดับจาก มากไปน้อย {91, 88, 79, 72, 65}

4. ## ($n$): 
จำนวนสมาชิกทั้งหมดในอาร์เรย์คะแนนสอบ

5. ## แนวคิด:
เปรียบเทียบข้อมูลที่อยู่ติดกันคู่ต่อคู่ หากตัวหน้าค่าน้อยกว่าตัวหลัง ให้ทำการสลับตำแหน่ง (Swap) เพื่อให้ค่ามากทยอยย้ายไปอยู่ด้านหน้า ในแต่ละรอบของการวนลูปหากไม่มีการสลับข้อมูลเกิดขึ้นเลย (swapped == false) แสดงว่าข้อมูลเรียงลำดับเรียบร้อยแล้ว จึงหยุดการทำงานได้ทันที

6. ## คำสั่งหลักที่ใช้วิเคราะห์คือ 
คำสั่งเปรียบเทียบข้อมูล (scores[j] < scores[j + 1])

7. ## (Best Case): 
ทำงาน $n - 1$ ครั้ง (ลูปนอกทำงานรอบเดียวแล้วหยุด)

8. ## Best Case: 
ข้อมูลเรียงลำดับเรียบร้อยแล้ว ใช้เวลาทำงานน้อยที่สุด

## Worst Case: 
ข้อมูลเรียงย้อนกลับทั้งหมด ต้องสลับข้อมูลทุกครั้งที่เปรียบเทียบ

## Average Case: 
ข้อมูลสุ่มกระจายทั่วไป

8. ## Time Complexity (Big O, Omega, Theta):  
Big O (Worst Case): $O(n^2)$
Big Omega (Best Case): $\Omega(n)$ (เฉพาะแบบปรับปรุงที่มี flag swapped)
Big Theta: ไม่สามารถระบุภาพรวมเป็น Theta เดียวได้เนื่องจาก Best Case และ Worst Case มี Complexity ต่างกัน (แต่ถ้าเป็น Bubble Sort แบบปกติจะตอบ $\Theta(n^2)$)

9. ## Auxiliary Space Complexity:
$O(1)$ เนื่องจากทำการจัดเรียงภายในอาร์เรย์เดิม (In-place) ใช้พื้นที่หน่วยความจำเพิ่มเติมเพียงแค่ตัวแปรชั่วคราว

 # คำตอบคำถามวิเคราะห์
 
 ## 1. Bubble Sort แบบปกติกับแบบปรับปรุงมี Best Case ต่างกันอย่างไร?
แบบปกติ (Unoptimized): มี ประสิทธิภาพเชิงเวลาในกรณีดีที่สุดเป็น $\mathcal{O}(N^2)$ เนื่องจากไม่มีตัวเช็กสถานะการสลับ โปรแกรมจึงต้องวนลูปเปรียบเทียบจนครบ $N-1$ รอบเสมอแบบปรับปรุง (Optimized): มี ประสิทธิภาพเชิงเวลาในกรณีดีที่สุดลดลงเหลือ $\mathcal{O}(N)$ เนื่องจากมีตัวแปร swapped ตรวจสอบ หากรอบแรกไม่มีการสลับข้อมูลเลย โปรแกรมจะหลุดออกจากลูป (break) ทันที (Early Exit)
 
 ## 2. Worst Case ของทั้งสองวิธีต่างกันหรือไม่?
ไม่ต่างกัน ทั้งสองวิธีมี ประสิทธิภาพเชิงเวลาในกรณีแย่ที่สุดเป็น $\mathcal{O}(N^2)$ เท่ากันเนื่องจากในกรณีที่ข้อมูลเรียงย้อนกลับ จะเกิดการสลับข้อมูลทุกครั้ง ทำให้ swapped = true เสมอ เงื่อนไข if (!swapped) break; จึงไม่ทำงาน ทำให้จำนวนรอบในการเปรียบเทียบและสลับข้อมูลเท่ากันทุกประการ

## 3. หากมีข้อมูลจำนวน 100,000 ค่า ควรเลือกวิธีนี้หรือไม่?
ไม่ควรเลือกใช้ Bubble Sort อย่างยิ่งเหตุผล: Bubble Sort มี ประสิทธิภาพเฉลี่ยและแย่ที่สุดอยู่ที่ $\mathcal{O}(N^2)$ หากมีข้อมูล $N = 100,000$ ค่า โปรแกรมต้องทำการเปรียบเทียบข้อมูลสูงถึงประมาณ 5,000,000,000 ครั้ง (5 พันล้านครั้ง) ซึ่งจะทำให้โปรแกรมทำงานช้ามากและใช้เวลาหลายนาทีข้อเสนอแนะ: ควรเปลี่ยนไปใช้อัลกอริทึมกลุ่ม Divide and Conquer ที่มีประสิทธิภาพระดับ $\mathcal{O}(N \log N)$ เช่น Quick Sort, Merge Sort หรือ Heap Sort ซึ่งสำหรับการเรียงข้อมูล 100,000 ค่า จะใช้การเปรียบเทียบเพียงประมาณ $1.7$ ล้านครั้ง และทำงานเสร็จภายในเวลาไม่กี่มิลลิวินาที
