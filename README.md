จำนวนครั้งของการเปรียบเทียบ: 9 ครั้ง

จำนวนครั้งของการสลับข้อมูล: 5 

# ครั้ง4–5. การวิเคราะห์กรณีข้อมูลเฉพาะ (Data Cases Analysis)กำหนดให้ $N$ คือจำนวนข้อมูลทั้งหมด  $N = 5$

## 4. กรณีข้อมูลเรียงแล้วอยู่แล้วจากมากไปน้อย (Best Case)ตัวอย่างข้อมูล: {91, 88, 79, 72, 65}Bubble Sort แบบปกติ (Unoptimized):จำนวนการเปรียบเทียบ: $\frac{N(N-1)}{2} = \mathbf{10}$ ครั้ง (วนลูปทำจนครบทุกรอบแม้ข้อมูลจะเรียงแล้ว)จำนวนการสลับ: $\mathbf{0}$ ครั้งBubble Sort แบบปรับปรุง (Optimized):จำนวนการเปรียบเทียบ: $N - 1 = \mathbf{4}$ ครั้ง (ตรวจสอบเฉพาะรอบแรก แล้วหยุดทันทีเพราะ swapped เป็น false)จำนวนการสลับ: $\mathbf{0}$ ครั้ง

## 5. กรณีข้อมูลเรียงย้อนกลับจากน้อยไปมาก (Worst Case)ตัวอย่างข้อมูล: {65, 72, 79, 88, 91} แต่ต้องการเรียงจากมากไปน้อยทั้งสองวิธีทำงานไม่ต่างกัน:จำนวนการเปรียบเทียบ: $\frac{N(N-1)}{2} = \mathbf{10}$ ครั้งจำนวนการสลับ: $\mathbf{10}$ ครั้ง (ต้องสลับข้อมูลทุกครั้งที่มีการเปรียบเทียบ)

 # คำตอบคำถามวิเคราะห์
 
 ## 1. Bubble Sort แบบปกติกับแบบปรับปรุงมี Best Case ต่างกันอย่างไร?แบบปกติ (Unoptimized): มี ประสิทธิภาพเชิงเวลาในกรณีดีที่สุดเป็น $\mathcal{O}(N^2)$ เนื่องจากไม่มีตัวเช็กสถานะการสลับ โปรแกรมจึงต้องวนลูปเปรียบเทียบจนครบ $N-1$ รอบเสมอแบบปรับปรุง (Optimized): มี ประสิทธิภาพเชิงเวลาในกรณีดีที่สุดลดลงเหลือ $\mathcal{O}(N)$ เนื่องจากมีตัวแปร swapped ตรวจสอบ หากรอบแรกไม่มีการสลับข้อมูลเลย โปรแกรมจะหลุดออกจากลูป (break) ทันที (Early Exit)
 
 ## 2. Worst Case ของทั้งสองวิธีต่างกันหรือไม่?ไม่ต่างกัน ทั้งสองวิธีมี ประสิทธิภาพเชิงเวลาในกรณีแย่ที่สุดเป็น $\mathcal{O}(N^2)$ เท่ากันเนื่องจากในกรณีที่ข้อมูลเรียงย้อนกลับ จะเกิดการสลับข้อมูลทุกครั้ง ทำให้ swapped = true เสมอ เงื่อนไข if (!swapped) break; จึงไม่ทำงาน ทำให้จำนวนรอบในการเปรียบเทียบและสลับข้อมูลเท่ากันทุกประการ

## 3. หากมีข้อมูลจำนวน 100,000 ค่า ควรเลือกวิธีนี้หรือไม่?ไม่ควรเลือกใช้ Bubble Sort อย่างยิ่งเหตุผล: Bubble Sort มี ประสิทธิภาพเฉลี่ยและแย่ที่สุดอยู่ที่ $\mathcal{O}(N^2)$ หากมีข้อมูล $N = 100,000$ ค่า โปรแกรมต้องทำการเปรียบเทียบข้อมูลสูงถึงประมาณ 5,000,000,000 ครั้ง (5 พันล้านครั้ง) ซึ่งจะทำให้โปรแกรมทำงานช้ามากและใช้เวลาหลายนาทีข้อเสนอแนะ: ควรเปลี่ยนไปใช้อัลกอริทึมกลุ่ม Divide and Conquer ที่มีประสิทธิภาพระดับ $\mathcal{O}(N \log N)$ เช่น Quick Sort, Merge Sort หรือ Heap Sort ซึ่งสำหรับการเรียงข้อมูล 100,000 ค่า จะใช้การเปรียบเทียบเพียงประมาณ $1.7$ ล้านครั้ง และทำงานเสร็จภายในเวลาไม่กี่มิลลิวินาที
